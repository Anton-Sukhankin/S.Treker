# Общая компонентная база S-Tracker

## 1. Назначение

Общая компонентная база является единственным корневым источником переиспользуемых UI-контролов и базовых паттернов текущего vanilla/Vite-прототипа. Разделы `Задачи`, `Поиск` и код локальных стендов используют эти реализации, но самостоятельно определяют данные, команды и продуктовые сценарии.

Компонентная база не заменяет продуктовые спецификации `docs/components/<component>/`. Она исключает повторную реализацию одинаковых кнопок, полей, селектов, чекбоксов, переключателей, пагинации и стандартных слоев интерфейса.

## 2. Источники

| Область | Источник |
|---|---|
| Реализация компонентов | `src/ui/components/` |
| Реестр компонентов | `src/ui/components/registry.js` |
| Общие стили | `src/styles/components/core-ui.css`, `src/styles/components/component-library.css` |
| Истории и состояния | `src/ui/components/*.stories.js` |
| Конфигурация каталога | `.storybook/` |
| Алиас потребителя | `@s-tracker/ui` из `vite.config.js` |

## 3. Правило единственного источника

1. История Storybook импортирует компонент из `src/ui/components/`; отдельная копия разметки компонента внутри истории не создается.
2. Feature-модуль импортирует общий компонент из `src/ui/components/` или через `@s-tracker/ui`.
3. Код локального стенда использует `@s-tracker/ui`; копии общих компонентов и их CSS внутри стенда не создаются.
4. Раздел-потребитель передает компоненту данные, подписи, доступность действий и обработчик результата.
5. Компонентная база не хранит правила фильтрации задач, поиска документов, состава колонок, массовых операций и других продуктовых сценариев.

## 4. Реестр

Каждый компонент имеет стабильный идентификатор, категорию, путь к модулю и перечень потребителей. Поле `dsBinding` остается `null` до отдельной разрешенной интеграции корпоративной дизайн-системы.

Агент или субагент сначала определяет нужный идентификатор в `registry.js`, затем использует указанную реализацию. Создание локального аналога допустимо только после подтверждения, что нужного компонента или варианта нет в реестре.

## 5. Текущая интеграция

| Компонент | Разделы, использующие общую реализацию |
|---|---|
| `ui.segmented-control` | Переключатель карточного и табличного вида задач |
| `pattern.pagination` | Список задач и результаты поиска документов |
| Остальные элементы реестра | Доступны для последовательного подключения без изменения продуктовой логики разделов |

Наличие компонента в Storybook не означает, что все ранее созданные места его использования уже мигрированы. Новые интерфейсы используют общую базу сразу; существующие области переводятся на нее отдельными проверяемыми изменениями.

## 6. Команды

| Команда | Результат |
|---|---|
| `npm run storybook` | Запускает интерактивный каталог на порту `6006`. |
| `npm run build-storybook` | Проверяет и собирает статический каталог в `storybook-static/`. |
| `npm run build` | Проверяет основное приложение S-Tracker. |

## 7. Граница будущей дизайн-системы

До прямой команды пользователя база остается на vanilla DOM API и текущих токенах S-Tracker. При миграции на корпоративную библиотеку стабильные идентификаторы сохраняются, `dsBinding` получает имя и версию корпоративного компонента, а локальная реализация заменяется адаптером без изменения продуктовых спецификаций разделов.
