# Карточка задачи: данные, состояния и правила

## Источники данных

| Данные | Источник |
|---|---|
| `id`, title, status, assignee, dueDate | Строка основной модели через `getTaskRowById(taskId)` |
| description, history, comments, конфигурация формы | `src/data/task-card-details.js` |
| Draft, сохранённые значения, активный и завершённые этапы | Экземпляр `createTaskCardState` для конкретного `taskId` |

## Состояния

Drawer имеет состояния `closed`, `default`, `history`, `comments`, `dirty-confirmation` и `resizing`. Одновременно смонтирован только один drawer; карта состояния может содержать независимые записи нескольких просмотренных задач.

Drawer является немодальным: у него нет активного overlay, `aria-modal` имеет значение `false`, а доступные наименования задач в рабочей области остаются интерактивными. При выборе другого `taskId` текущий экземпляр заменяется новым, а состояние формы хранится независимо по каждому `taskId`.

`history` содержит пять позиций, `comments` — четырнадцать позиций текущего mock-набора. При пустом массиве вместо списка видна текстовая заглушка.

## Контракты

- Компонент получает `taskId` только из `.js-open-task-card[data-task-id]`.
- Наименование задачи — единственная точка входа; чекбокс `.js-task-select` продолжает управлять только массовым выбором.
- Drawer не записывает данные в `window.__taskDataMap` и не владеет состояниями списка задач или раздела `Поиск`.
- Все поверхности аккордеонов, карточки этапов и комментарии не имеют тени.
