# План реализации локального стенда документных сценариев

## 1. Статус и назначение

План является рабочей последовательностью для многостраничного runtime в едином корне `local-stands/` и его контекстного контура `local-stands/document-workflows/`. По мере выполнения пункты отмечаются в этом файле. Изменение порядка волн требует явного решения и обновления связанных компонентных спецификаций.

## 2. Неподвижные правила

| Правило | Проверяемый результат |
|---|---|
| Изоляция | Весь новый код, mock-данные, стили и продуктовые документы находятся внутри корня стенда. |
| Нет двойной реализации | Основной S-Tracker не импортирует стенд; стенд не импортирует корневой runtime S-Tracker. |
| Общая Lego-форма | Разделы `Задачи` и `Документы` используют одну реализацию `../src/shared/lego-document-form/`. |
| Документация перед кодом | До реализации компонента его `01/02/03` отражают утвержденную границу и основной путь. |
| Гипотезы | Неопределенное предложение из встречи не реализуется как требование. |
| Миграция | Готовый блок переносится один раз вместе с кодом и документацией по `migration/README.md`. |
| Зависимости | React, Tend UI, Material UI и новые зависимости не добавляются без прямой команды пользователя. |

## 6. Волна 1 — первый интерфейс: карточка задачи в drawer

### 6.1. Подтвержденная граница

Первый экран стенда открывается в разделе `Задачи`. В основной области находится одна компактная демонстрационная строка mock-задачи:

| Элемент | Значение или правило |
|---|---|
| Номер | Стабильный mock-идентификатор задачи. |
| Наименование | `Создайте заявку на потребность АХР`. |
| Статус | Начальное состояние процесса из mock-данных. |
| Действие | Кнопка `Открыть карточку`. |

Кнопка является стендовой точкой входа. Она не мигрируется как новый список задач и не дублирует действующий компонент списка S-Tracker.

После нажатия справа раскрывается drawer карточки. Экран-источник остается виден под overlay и не меняет активный раздел или маршрут. Обязательная кнопка закрытия находится в заголовке drawer и возвращает пользователя к той же демонстрационной строке.

## 13. Правило ведения плана

1. Перед началом волны проверить ее документационные входы и открытые решения.
2. В один момент выполнять только одну волну и один ограниченный функциональный срез.
3. После каждого среза обновить чекбоксы, связанные спецификации и фактический результат проверки.
4. Не отмечать пункт завершенным по наличию файла: требуется видимый и проверенный результат.
5. Если новое решение меняет границу, сначала обновить спецификацию и flow, затем код.
6. Любое изменение за пределами `local-stands/` требует отдельной миграционной команды пользователя.
