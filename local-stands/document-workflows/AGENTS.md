# AGENTS.md

## Область действия

Инструкции действуют для документации, исследования, референсов и миграционных материалов в `local-stands/document-workflows/`.

## Назначение

Это контекстный и спецификационный контур локального стенда документных сценариев S-Tracker. Runtime, mock-данные и стили стенда находятся уровнем выше, в `local-stands/`; они не размещаются в runtime-файлах основного прототипа.

## Правила изоляции

1. Новый runtime-код стенда создается только в `local-stands/src/`; его правила и границы фиксируются в этом контуре. Исходники MagicPath в `local-stands/magicpath/` остаются изолированными вариантами дизайна и не подключаются к runtime автоматически.
2. Новая документация стенда создается только в `local-stands/document-workflows/docs/`.
3. Компоненты стенда не импортируют feature-, domain- и data-модули корневого S-Tracker. Единственное разрешенное исключение - общая компонентная база через `@s-tracker/ui`; локальные копии ее компонентов и стилей запрещены.
4. Основной S-Tracker не импортирует файлы стенда до отдельной миграционной задачи.
5. Не копировать спецификации стенда в корневой `docs/` для навигации или «временной регистрации».
6. Общие требования к качеству документации берутся из корневого `docs/documentation-standards.md`; локальная копия стандарта не создается.
7. Миграция выполняется по одному завершенному блоку вместе с его кодом, документацией, данными, стилями и проверками.

## Ограничения реализации

- Не подключать React, Tend UI, Material UI и новые зависимости без прямой команды пользователя.
- Не менять действующие вкладки `Задачи` и `Поиск` основного S-Tracker во время работы над стендом.
- Не использовать действующий runtime документного поиска как скрытую реализацию нового раздела `Документы`.
- Сначала сохранять работоспособность стенда, затем выполнять рефакторинг.

## Документация

Компонентные комплекты используют `01-structure.md`, `02-behavior.md`, `03-data-states-rules.md` и проверяются по корневому `docs/documentation-standards.md` с рабочей процедурой `component-spec-audit`.

Каждый раздел имеет паспорт `docs/sections/<section>/README.md`. Паспорт фиксирует границу раздела, состав задач, ссылки на компоненты и flow, идентификаторы источников и готовность к прототипированию. Он не повторяет правила из `01/02/03`.

Источники регистрируются один раз в `references/context-register.md`. Раздел использует выборку `references/evidence/<section>/README.md`; факт переносится в компонентную спецификацию только после отделения от замечаний и гипотез.

Новая папка компонента создается только для самостоятельной интерфейсной границы или переиспользуемого блока. Маленькая задача внутри существующего компонента остается пунктом паспорта раздела и рабочего плана.

До начала кода целевого блока должны быть определены его компонент-владелец, подтвержденные источники, применимые `01/02/03`, связанный flow и открытые решения. Гипотеза не считается требованием без явного решения пользователя.
