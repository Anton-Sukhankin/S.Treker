# План миграции `New Document Type Picker` как нижнего drawer

> Статус: выполнено в локальном стенде 03.08.2026. Нижний picker, ECM- и Lego-маршрутизация, локальное сохранение, документация и browser-проверка завершены; перенос в основной S-Tracker и backend остаются отдельной задачей.

## 1. Цель

Перенести согласованный вариант `S Tracker New Document Picker Managed Catalog` из MagicPath в нативный vanilla/Vite-runtime локального стенда и показывать его как модальный drawer, который раскрывается от нижней границы рабочей области вверх после нажатия `Создать новый документ` в разделе `Документы`.

После миграции пользователь должен:

1. выбрать пакет в разделе `Документы`;
2. нажать `Создать новый документ`;
3. найти тип документа или шаблон в нижнем drawer;
4. выбрать стандартную ECM-форму или опубликованный Lego-шаблон;
5. перейти в соответствующую форму создания с сохраненным контекстом пакета;
6. после успешного сохранения увидеть новый документ в таблице того же пакета.

Сам picker не создает документ по нажатию `Выбрать`. Он передает выбранный вариант и текущий пакет форме создания. Документ появляется в таблице только после успешного подтверждения формы. Это исключает ложную готовность backend-функции и соответствует действующему flow.

## 4. Граница инкремента

### Входит

- нижний modal drawer и его интеграция с общим `pattern.drawer`;
- открытие по `Создать новый документ` при доступном действии;
- header, пояснение, поиск, счетчик, заголовок колонок, список вариантов и действия `Выбрать`;
- колонка `Источник / Тип` с двухстрочным значением и отдельной иконкой источника;
- поиск по наименованию варианта и отображаемому источнику;
- пустое состояние поиска;
- закрытие кнопкой в header, `Escape` и overlay;
- возврат фокуса на `Создать новый документ` после закрытия без выбора;
- сохранение текущего пакета, страницы, сортировки, фильтров и выделения таблицы;
- передача выбранной ECM-формы или Lego-шаблона следующему компоненту;
- возвращение нового документа в текущий пакет после успешного сохранения формы;
- mock-данные и интерфейсный контракт ошибок/загрузки без backend-реализации;
- обновление компонентных спецификаций, flow и визуальных эталонов.

### Не входит

- backend API, база данных и постоянное серверное хранение;
- создание или публикация Lego-шаблонов;
- боковая навигация источников и категорий;
- отдельные фильтры кроме текстового поиска;
- изменение вкладки `Поиск` и ее document runtime;
- новый UI-kit, React, TSX, `lucide-react` или новая npm-зависимость;
- редизайн таблицы документов, панели пакетов или карточки документа;
- одновременное отображение picker drawer и правой карточки документа.

## 5. Пространственный контракт

| Зона | Расположение и слой | Видимый состав | Влияние на раздел `Документы` |
|---|---|---|---|
| Overlay | Поверх всей рабочей области после нажатия `Создать новый документ` | Нейтральное затемнение без самостоятельных действий | Блокирует действия дерева пакетов, таблицы и toolbar до закрытия picker. |
| Bottom drawer | Привязан к нижней границе viewport; занимает всю доступную ширину и большую часть высоты, но сохраняет видимый верхний контекст раздела | Header, поиск и прокручиваемый список | Не сдвигает дерево пакетов, toolbar и таблицу; закрытие возвращает их в прежнее состояние. |
| Header | Верхняя закрепленная зона drawer | `Загрузка нового документа`, пояснение, кнопка закрытия | Остается видимым при прокрутке списка. |
| Поиск и счетчик | Под header, над колонками | Поле поиска, очистка, `Найдено: N` | Поиск меняет только строки текущего picker. |
| Список | Центральная прокручиваемая зона | `Тип документа / шаблон`, `Источник / Тип`, `Выбрать` | Прокрутка списка не прокручивает страницу под overlay. |

Рабочая геометрия для первого прототипа: высота drawer ограничивается доступной высотой viewport и на desktop не должна закрывать верхнюю навигацию раздела полностью. Конкретная формула высоты утверждается по browser screenshot до фиксации `01-structure.md`; нельзя уменьшать типографику или убирать колонку `Источник / Тип` только ради размещения.

На узком viewport drawer переходит к почти полноэкранной высоте. Колонка `Источник / Тип` не исчезает без отдельного продуктового решения: при нехватке ширины она переносится под наименование варианта внутри строки, а действие `Выбрать` остается доступным.

## 6. Состояния и владельцы

| Состояние | Владелец | Условие входа | Видимый результат | Условие выхода |
|---|---|---|---|---|
| Picker закрыт | `documents-workspace` | Базовое состояние раздела | Drawer и overlay отсутствуют | Нажатие доступной кнопки создания. |
| Picker открыт | `documents-workspace` | Нажато `Создать новый документ` | Bottom drawer виден; текущий пакет сохранен | Закрытие или выбор варианта. |
| Поиск активен | Picker | Введен непустой запрос | Видны только подходящие варианты; счетчик равен числу видимых вариантов | Очистка или закрытие drawer. |
| Пустой результат | Picker | Нет совпадений | Одна пустая заглушка и действие очистки; фиктивных строк нет | Изменение или очистка запроса. |
| Вариант выбран | Picker | Нажато `Выбрать` в доступной строке | Picker передает `packageId`, `source`, `optionId` и отображаемое имя получателю | Открытие формы или видимая ошибка запуска. |
| Форма создания открыта | `documents-workspace` и компонент формы | Получатель принял контекст | Picker закрыт; форма показывает выбранный тип или шаблон | Сохранение или отмена. |
| Документ создан | `documents-workspace` | Форма вернула успешный результат | Таблица текущего пакета содержит новый документ; счетчик и пагинация пересчитаны | Дальнейшие действия пользователя. |

При открытии picker закрываются меню toolbar и строки. Если правая карточка документа открыта, она закрывается до показа bottom drawer, но выбранный пакет и табличное состояние сохраняются. Одновременно активен только один верхнеуровневый drawer раздела.

## 7. Целевые данные

В `documents-workspace-mock.js` добавляется отдельная коллекция вариантов создания. UI не создает варианты внутри функции рендера.

Минимальный интерфейс каждого варианта:

| Поле | Назначение |
|---|---|
| `id` | Стабильный идентификатор варианта. |
| `name` | Основное наименование строки. |
| `source` | `ecm` или `lego`. |
| `sourceLabel` | `Стандартная ECM-форма` или `Lego-шаблон`. |
| `documentTypeId` | Тип будущего документа. |
| `templateVersionId` | Версия опубликованного Lego-шаблона; для ECM отсутствует. |
| `published` | Lego-вариант показывается только при опубликованном состоянии. |
| `available` | Определяет доступность выбора для текущего контекста и роли. |

Текущие 13 строк Managed Catalog являются примером данных прототипа, а не постоянным полным списком системы. Порядок и состав будущего списка задаются данными и правами, не UI.

Чистая domain-функция получает варианты, запрос и контекст пакета; возвращает отображаемый список без DOM и без изменения исходных данных.

## 9. Контракт общего bottom drawer

Техническое расширение `createDrawer` должно:

- сохранить текущее значение `right` по умолчанию;
- добавлять placement-класс без изменения публичного поведения существующих потребителей;
- для `bottom` использовать `translateY(100%)` в закрытом состоянии и `translateY(0)` в открытом;
- анимировать только `transform` и `opacity`;
- использовать отзывчивый custom ease-out; вход ориентировочно `220–280 ms`, выход быстрее входа;
- при `prefers-reduced-motion: reduce` убрать перемещение и сохранить короткую opacity-индикацию;
- поддерживать modal overlay, закрытие по overlay и `Escape`;
- переводить фокус в drawer после открытия, удерживать фокус внутри modal-слоя и возвращать его trigger после закрытия;
- блокировать прокрутку документа под открытым modal drawer;
- не закрывать другой слой вторым обработчиком `Escape` после того, как верхний слой обработал событие.

В продуктовой спецификации фиксируются условия открытия, закрытия и видимый результат. Внутренняя механика focus trap, scroll lock и анимации остается документацией общего компонента и тестами, а не повторяется в `03-data-states-rules.md` picker.

**Шлюз:** source snapshot, визуальный baseline и закрытый список отличий доступны до начала кода.

### WP-01. Расширение общего Drawer

- добавить `bottom` placement без изменения default `right`;
- добавить Storybook-состояние;
- проверить текущих потребителей Drawer;
- отдельно проверить `Escape`, overlay, возврат фокуса, scroll lock и reduced motion.

**Шлюз:** существующие правые drawer визуально и функционально не изменились; bottom drawer открывается и закрывается независимо от содержимого.

### WP-02. Данные и правила отбора

- добавить mock-варианты создания;
- реализовать чистый поиск по `name`, `sourceLabel` и дополнительным индексируемым значениям;
- исключать неопубликованные Lego-шаблоны и недоступные варианты;
- покрыть поиск, пустой результат и применимость unit-проверками, если текущий test harness это поддерживает.

**Шлюз:** domain-слой возвращает детерминированный список и не содержит DOM.

### WP-03. Нативный picker

- перенести иерархию Managed Catalog без React и Tailwind runtime;

**Шлюз:** picker работает изолированно с representative data и совпадает с baseline во всех областях, кроме согласованного bottom-drawer контейнера.

### WP-04. Интеграция с разделом `Документы`

- заменить демонстрационный toast кнопки создания на отдельный callback открытия;
- сохранить выбранный пакет и состояние таблицы;
- закрывать конфликтующие меню и правую карточку документа до открытия picker;
- mount/destroy drawer вместе с workspace;
- возвращать фокус на trigger после отмены.

**Шлюз:** кнопка открывает drawer снизу вверх; закрытие возвращает пользователя в тот же пакет и табличное состояние.

### WP-05. Маршрутизация выбора и результат создания

- ECM-вариант передает контекст стандартной форме;
- Lego-вариант передает `packageId`, `documentTypeId` и `templateVersionId` общему `lego-document-form`;
- при ошибке запуска picker остается доступным или открывается повторно с видимой ошибкой;
- при отмене формы пользователь возвращается в тот же пакет без новой строки;
- при успешном сохранении новая строка появляется в текущем пакете, счетчик и пагинация пересчитываются.

**Шлюз:** picker не имитирует создание toast-сообщением; видимый новый документ возникает только из успешного результата формы.

### WP-06. Документация и визуальные эталоны

- синхронизировать `new-document-type-picker/01/02/03` с фактическим стендом;
- обновить `documents-workspace/01/02/03` только в затронутых разделах;
- обновить flow `create-document-from-documents-workspace.md`;
- сохранить локальный скриншот открытого bottom drawer с минимальным соседним контекстом;
- обновить карту кода и паспорт раздела, если новые файлы стали частью фактического runtime.

**Шлюз:** компонентные документы прошли `component-spec-audit`, а flow не дублирует локальную структуру picker.

### WP-07. Функциональная и визуальная приемка

- применить `typeset` только при подтвержденной проблеме читаемости;
- устранить блокирующие отклонения и повторить проверки.

**Шлюз:** критерии разделов 11 и 12 выполнены без блокирующих отклонений.

| `frontend-design` | WP-00, WP-03 | Сначала собрать контекст продукта: существующие токены, стили, общие контролы, плотность таблиц и соседние drawer; строить в языке S-Tracker | Не вводить новое визуальное направление и новые зависимости. |

| `animations` | WP-01, WP-04 | Bottom drawer скрывается собственным `translateY(100%)`; используются transform/opacity, custom ease-out, быстрый выход, reduced motion и interruptible transitions | Декоративное движение не должно задерживать доступ к поиску и списку. |
| `typeset` | Только подтвержденная проблема | Проверить иерархию header, основного имени и вторичной строки, читаемость при 200% zoom, длинные значения и табличное выравнивание | Не заменять шрифт S-Tracker и не проводить общий типографический редизайн. |
| `polish` | Только после WP-05 | Проверить alignment, spacing, состояния, copy, иконки, длинные значения, responsiveness, accessibility, performance и console | Не полировать нефункциональный flow и не внедрять предложения вне baseline без решения пользователя. |

Приоритет при конфликте:

1. текущее требование пользователя;
2. сохранение функциональности, accessibility и данных локального runtime;
3. согласованный Managed Catalog и закрытый список отличий;
4. компонентные спецификации;
5. рекомендации quality skill.

## 14. Риски

| Риск | Ограничение |
|---|---|
| Одноименные MagicPath-компоненты | Фиксировать источник по component ID, revision и preview. |
| Копирование TSX в vanilla-runtime | Использовать TSX только как источник структуры; реализовать нативный модуль без React и новых зависимостей. |
| Локальная копия Drawer | Сначала расширить общий `pattern.drawer`; проверить всех существующих потребителей. |
| Общий `Escape` закрывает два слоя | Ввести стек/приоритет верхнего overlay и проверять propagation. |
| Drawer перекрывает важный контекст | Сохранить верхний контекст раздела и проверить высоту по скриншоту, а не случайным CSS-смещением. |
| Категорийная фильтрация возвращается при переносе | Source of truth — согласованная ревизия без sidebar; в данных нет UI-категорий picker. |
| Picker имитирует создание | Новый документ появляется только после успешного результата формы. |
| Mock-данные становятся продуктовым перечнем | Текущие строки помечены как пример; UI получает динамический список. |
| Polish меняет визуальный контракт | Любое предложение вне baseline оформляется отдельным delta и требует решения пользователя. |
| Документация опережает код без маркировки | До приемки все изменения помечаются как целевая спецификация будущего состояния. |

## 15. Definition of Done

- зафиксирован долговечный источник `cozy-moon-2576` и визуальный baseline;
- `Создать новый документ` открывает bottom drawer, а не демонстрационный toast;
- drawer сохраняет структуру согласованного Managed Catalog без боковой панели категорий;
- колонка `Источник / Тип` соответствует согласованному двухстрочному виду;
- общий Drawer поддерживает `bottom`, а существующие правые drawer не изменились;
- поиск, пустое состояние, закрытие, keyboard path, focus return и reduced motion работают;

- ECM- и Lego-варианты передают правильный контекст форме;
- новый документ появляется только после успешного сохранения формы;

- сборка, регрессия, visual comparison, accessibility и console-проверка пройдены;
- `01/02/03`, flow, визуальные эталоны и карта кода соответствуют фактическому стенду;
