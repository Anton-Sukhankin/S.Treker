# Миграция Lego в локальный стенд «Документы»

## 1. Цель и конечное состояние

После миграции пользователь открывает `Загрузку нового документа`, выбирает опубликованный Lego-шаблон и продолжает работу в том же нижнем drawer. Каталог вариантов заменяется самостоятельным пятиэтапным интерфейсом Lego; подтверждение последнего этапа открывает сводку; сохранение сводки добавляет документ в текущий пакет раздела `Документы`.

Отдельная HTML-точка входа Lego не создаётся. Общая модель и общий рендерер формы остаются доступны встроенному виджету карточки задачи. Исходник MagicPath используется как зафиксированный визуальный источник и не импортируется в runtime.

## 3. Последовательность реализации

### Волна A. Модель данных и состояния

1. Перенести подтверждённый состав пяти этапов, справочники, начальные значения и параметры сводки в `local-stands/src/data`.
2. Выделить независимое состояние Lego с draft/saved values, последовательным разблокированием этапов, валидацией и переходом `form → summary`.
3. Сохранить совместимый адаптер `createTaskCardState`, чтобы карточка задачи не получила собственную копию состояния.

Критерий завершения: один snapshot обслуживает самостоятельный и встроенный режимы; изменение завершённого этапа блокирует его и последующие этапы до повторного подтверждения.

### Волна B. Общий интерфейс Lego

1. Перенести карточки пяти этапов, формы и условные поля из зафиксированной ревизии MagicPath.
2. Реализовать серые placeholder-значения select до выбора и обычный цвет после выбора.
3. Убрать белые подложки и внутренние padding у toggle-строк.
4. Сохранить разделители и одноколоночные смысловые блоки этапов `Контрагент` и `Стоимость и бюджет`.
5. В самостоятельном режиме зафиксировать header, карточки этапов и footer; скроллировать только контентную область между ними.
6. Встроенный режим оставить внутри аккордеона карточки задачи; footer действий принадлежит drawer задачи.

Критерий завершения: все пять этапов доступны последовательно, обязательные поля валидируются, а компоновка не создаёт горизонтальный скролл при поддерживаемой ширине.

### Волна C. Сводка

1. После подтверждения пятого этапа заменить экран формы экраном сводки.
2. Разместить фиксированный header со статусом и действиями справа.
3. Показать слева по одному белому блоку на этап; каждое значение разместить в отдельной паре `label/value` с ячеистой компоновкой без disabled-контролов.
4. Разместить справа фиксированную область финальной проверки с пояснением, иллюстрацией, сохранением документа и возвратом к редактированию.
5. На узкой ширине перестроить правую область под список блоков без потери доступности действий.

Критерий завершения: левая колонка скроллируется независимо; header и правая область остаются видимыми; возврат открывает пятый этап с сохранёнными значениями.

### Волна D. Интеграция в «Документы»

1. Для ECM-вариантов сохранить существующую общую форму создания документа.
2. Для Lego-вариантов скрыть общий header drawer и отдать весь доступный viewport самостоятельному Lego-shell.
3. Перенести `Вернуться к выбору` из footer в header интерфейса Lego.
4. После финального сохранения передать выбранный шаблон и значения формы в владельца раздела `Документы`, добавить строку в текущий пакет и закрыть drawer.
5. При повторном открытии начать новый независимый draft.

Критерий завершения: путь `Создать новый документ → Выбрать Lego → 5 этапов → Сводка → Сохранить документ` выполняется в одном drawer и заканчивается новой строкой списка.

### Волна E. Карточка задачи

1. Подключить расширенную общую форму к существующему виджету карточки задачи.
2. Сохранить действия `Сохранить` и `Подтвердить шаг` в фиксированном footer drawer задачи.
3. Не открывать самостоятельную сводку внутри карточки задачи; подтверждение пятого этапа завершает задачу.

Критерий завершения: список задач, открытие drawer, история, комментарии, resize, сохранение draft и защита от закрытия с несохранёнными значениями работают как ранее.

### Волна F. Документация и проверка

1. Обновить комплект `lego-document-form/01-structure.md`, `02-behavior.md`, `03-data-states-rules.md`.
2. Обновить сквозные сценарии создания документа и заполнения формы в задаче.
3. Обновить паспорта разделов, README общей реализации и карту фактических runtime-владельцев внутри локального контура.
4. Выполнить production build, ручной browser-smoke обоих режимов, keyboard/focus-проверку и проверку отсутствия импортов из `local-stands/magicpath`.

Критерий завершения: документация описывает фактический runtime; сборка проходит; все зафиксированные пользовательские пути воспроизводятся.

## 4. Вывод отдельного Lego-контура из эксплуатации

Исходник MagicPath не удаляется до выполнения всех критериев волн A–F и переноса необходимых визуальных эталонов в компонентный комплект. После проверки он может быть перемещён в архив источников или удалён отдельным безопасным действием. До этого момента каталог `local-stands/magicpath/lego-form/standalone-steps/` остаётся доказательством выбранной ревизии, но не является запускаемым стендом и не участвует в сборке.

## 5. Регрессионный периметр

- открытие каталога `Загрузка нового документа`;
- поиск и выбор ECM- и Lego-вариантов;
- создание ECM-документа;
- добавление Lego-документа в текущий пакет;
- открытие карточки задачи и работа её footer;
- история, комментарии, resize и закрытие карточки задачи;
- сборка всех четырёх HTML-точек локального стенда.
