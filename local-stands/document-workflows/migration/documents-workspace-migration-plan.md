# План миграции `documents-workspace` из MagicPath в локальный стенд

> Статус: первая миграция в `local-stands` выполнена по revision `434701870192275456`; интеграция в основной runtime S-Tracker выполняется только после прохождения миграционного шлюза. Следующие инкременты перечислены в разделе 14.

## 1. Цель и конечный результат

Перенести утвержденное интерактивное состояние раздела `Документы` из MagicPath в нативный vanilla/Vite-runtime локального стенда без React, новых зависимостей и импорта feature-, domain- или data-runtime основного S-Tracker.

После завершения базовой миграции URL `/documents/` должен показывать рабочую область документов вместо заглушки. Интерфейс должен сохранять визуальный контракт MagicPath, использовать общие контролы через `@s-tracker/ui` и оставаться изолированным от вкладки `Поиск` основного прототипа.

Миграция считается переносом текущей реализации, а не поводом добавить поведение, отсутствующее в MagicPath и действующей спецификации.

## 3. Граница первой миграции

### 3.1. Входит в паритет текущей ревизии

- трехзонная панель пакетов с закрепленными поиском и footer;
- дерево пакетов до четвертого уровня, раскрытие, выбор и поиск;
- обрезка длинного имени пакета и подсказка полного значения;
- изменение ширины панели в диапазоне `272–560 px`, базовая ширина `320 px`, возврат двойным кликом;
- контекст выбранного пакета и счетчик документов;
- панель инструментов списка и реализованные mock-реакции ее действий;
- включение вложенных пакетов, сортировка и фильтр типа документа;
- таблица документов, выбор строк, меню строки и настраиваемые видимые колонки;
- пагинация при количестве документов больше `25` и размеры страницы `25`, `50`, `100`;
- плавающая панель массовых действий;
- открытие карточки по наименованию и переключение документа без закрытия drawer;
- drawer шириной `1060 px` во фрейме `1600 px`;
- header карточки, выбор версии, меню `Действия` и копирование ссылки;
- блок атрибутов, панель файлов шириной `350 px`, промежуток между блоками `12 px`;
- footer карточки только с действиями `Закрыть` и `Редактировать атрибуты`;
- toast-подтверждения текущих демонстрационных действий;
- keyboard- и focus-поведение, уже зафиксированное спецификацией.

### 3.2. Не входит в первую миграцию

Следующие состояния остаются отдельными инкрементами, потому что в текущей ревизии MagicPath отсутствует их полное рабочее поведение:

- встроенный просмотр файла;
- фактическое редактирование и сохранение атрибутов;
- выбор способа создания документа;
- самостоятельная Lego-форма создания;
- создание, версия, удаление, скачивание и изменение документа на backend;
- интеграция с основным разделом S-Tracker;
- изменение вкладки `Поиск` и ее документного runtime.

Кнопки этих действий в первой миграции сохраняют только подтвержденную mock-реакцию MagicPath. Они не должны создавать видимость завершенной продуктовой функции.

## 4. Целевая архитектура локального стенда

| Ответственность | Целевой файл или папка | Правило |
|---|---|---|
| Запуск раздела | `local-stands/src/entries/documents.js` | Заменяет заглушку композицией рабочего раздела; не содержит бизнес-правил. |
| Композиция и состояние | `local-stands/src/sections/documents/index.js` | Создает workspace, связывает дочерние зоны и владеет выбранным пакетом, открытым документом и связями состояний. |
| Панель пакетов | `local-stands/src/sections/documents/package-sidebar.js` | Рендерит дерево, поиск, выбор, раскрытие и resize; не фильтрует документы самостоятельно. |
| Панель и таблица | `local-stands/src/sections/documents/documents-list.js` | Рендерит контекст пакета, toolbar, таблицу, выбор строк и меню строки. |
| Карточка документа | `local-stands/src/sections/documents/document-detail-drawer.js` | Рендерит header, атрибуты, файлы, footer и меню действий выбранного документа. |
| Данные стенда | `local-stands/src/data/documents-workspace-mock.js` | Содержит дерево пакетов, документы, атрибуты, версии и файлы без DOM-логики. |
| Чистые правила пакетов | `local-stands/src/domain/document-packages.js` | Поиск узлов, путь, фильтрация дерева, раскрытие и операции с mock-структурой. |
| Чистые правила списка | `local-stands/src/domain/documents-table.js` | Получение документов пакета, вложенные документы, сортировка, фильтр и пагинация. |
| Производные данные карточки | `local-stands/src/domain/document-detail.js` | Возвращает атрибуты и файлы выбранной версии без создания DOM. |
| Стили раздела | `local-stands/src/styles/documents-workspace.css` | Все правила ограничены корневой областью раздела и не изменяют `tasks` или `document-templates`. |

Названия файлов являются целевым маршрутом реализации. Главный агент может объединить два маленьких модуля, если после реализации граница не имеет самостоятельного состояния, но не переносит бизнес-правила в DOM-рендер.

## 5. Обязательные архитектурные ограничения

1. Не переносить React-компонент, hooks, TSX или `lucide-react` в нативный стенд.
2. Не добавлять React, Tend UI, Material UI и новые npm-зависимости.
3. Кнопки, Input, Select, Checkbox, Pagination, Drawer и Toast получать через `@s-tracker/ui`, если соответствующий компонент покрывает требуемое состояние.
4. Перед созданием локального UI-контрола проверить `src/ui/components/registry.js` и реальный экспорт `src/ui/components/index.js`.
5. Mock-данные не хранить в UI-модулях и не генерировать внутри функций рендера.
6. Чистые функции domain-слоя не читают и не изменяют DOM.
7. Стили раздела должны иметь общий scope и не переопределять базовые классы вне workspace.
8. `local-stands/dist` не редактировать; он пересоздается командой сборки.
9. MagicPath остается визуальным источником, но не runtime-зависимостью локального стенда.
10. Вкладка `Поиск` и ее состояние не используются как скрытый источник реализации раздела `Документы`. Допускается повторное использование общей пагинации и зарегистрированных UI-компонентов.

### 5.1. Подтвержденные разрывы общей компонентной базы

| Компонент | Текущее ограничение | Требование раздела | Решение до реализации потребителя |
|---|---|---|---|
| `pattern.drawer` | Текущая реализация всегда создает overlay, устанавливает `aria-modal="true"` и переводит фокус на drawer. | Карточка документа немодальна: видимая часть таблицы остается доступной для переключения документа. | Добавить обратно совместимую конфигурацию немодального режима в общий компонент или зарегистрировать общий вариант detail drawer. Значения по умолчанию не должны менять существующих потребителей. |
| `pattern.pagination` | `totalPages` фиксируется при создании, публичного обновления общего количества страниц нет. | Количество страниц меняется после выбора пакета, фильтра, вложенных документов и размера страницы. | Либо безопасно пересоздавать Pagination с восстановлением текущей страницы, либо добавить обратно совместимый метод обновления `totalPages`; решение фиксируется до WP-04. |

Локальная копия Drawer или Pagination внутри `documents-workspace` не допускается. Изменение общей компонентной базы сопровождается проверкой существующих потребителей и Storybook-состояний.

### 5.2. Оркестрация skills и quality gates

На дату фиксации плана в личной рабочей области MagicPath включены публичные skills `magicpath-design`, `typeset` и `polish`. Они применяются в MagicPath-контексте и не изменяют локальный код автоматически. Локальные Codex skills используются отдельно для проверки переноса, спецификаций и нативной реализации.

| Этап | Skill | Когда применять | Обязательный результат | Ограничение |
|---|---|---|---|---|
| Фиксация визуального источника | `magicpath` | WP-00 и при появлении новой согласованной ревизии | Точный component/revision, source snapshot через read-only `code context`, reference viewport и визуальный baseline | Для vanilla/Vite-стенда не выполнять `add`; TSX используется как источник для перевода, а не устанавливается в runtime. |
| Проверка MagicPath-дизайна | `magicpath-design` | Перед заморозкой baseline и после значимого изменения на холсте | Однострочный вердикт по spacing, typography, contrast, alignment, artboard fit и repetition; найденные проблемы исправлены точечно | Не перестраивать весь компонент и не менять установленный язык интерфейса без запроса пользователя. |
| Типографическая проверка | `typeset` | Только если выявлена конкретная проблема читаемости, иерархии или консистентности текста | Зафиксированы роли текста, размеры, веса, line-height, контраст и поведение длинных значений | Не запускать как автоматический редизайн. Предлагаемое изменение типографики становится отдельным согласованным delta к baseline; обязательная подготовка самого skill должна быть доступна. |
| Финальная визуальная доводка | `polish` | Только после функциональной приемки WP-07 | Проверены alignment, spacing, interaction states, copy, icons, edge cases, responsiveness, accessibility, performance и console | Polish не предшествует функциональной готовности. Каждая правка повторно проходит регрессию и visual diff; обязательная подготовка самого skill должна быть доступна. |
| Аудит спецификации | `component-spec-audit` | WP-00 и WP-08, а также после изменения видимого контракта | `01/02/03` конкретны, соответствуют стенду и не смешивают структуру, поведение и состояния | Skill не добавляет будущую функциональность и не расширяет границу первой миграции. |
| Аудит frontend-кода | `frontend-code-audit` | После изменения общей компонентной базы, после WP-07 и перед шлюзом в основной S-Tracker | Нет дублирования компонентов, утечек событий, небезопасного DOM-рендера, регрессий accessibility и необоснованных зависимостей | Аудит не является разрешением на React-миграцию, рефакторинг вне scope или изменение основного runtime. |
| UX/UI-аудит результата | `product-design:audit` | После интеграции WP-07 и повторно после исправлений WP-08 | Сначала получены скриншоты ключевых состояний, затем оформлены доказательные UX, visual и accessibility findings | Замечания сравниваются с baseline и спецификацией; изменение продукта требует отдельного решения, а не скрытого исправления. |
| Браузерная проверка | `browser:control-in-app-browser` | На приемке каждого интерактивного WP | Проверены реальные действия, focus, keyboard, viewport, bounding boxes, console и runtime-ошибки | DOM-проверка не заменяет визуальный скриншот; один скриншот не заменяет проверку поведения. |

#### Правило приоритета skills

Если рекомендация skill конфликтует с миграционным контрактом, применяется следующий порядок:

1. явное текущее требование пользователя;
2. сохранение необходимой функциональности, accessibility и данных локального runtime;
3. точный baseline ревизии MagicPath;
4. утвержденная компонентная спецификация;
5. рекомендация quality skill.

Конфликт не решается скрытым компромиссом. Главный агент фиксирует конкретное различие и запрашивает продуктовое решение. До решения сохраняется baseline.

#### Артефакт прохождения quality gate

Каждый вызванный skill должен оставить в отчете рабочего пакета:

- skill и причина его применения;
- проверенные состояния и viewport;
- найденные отклонения с доказательством;
- исправленные файлы или осознанно сохраненный baseline;
- повторные проверки после исправления;
- нерешенные вопросы и требуемое решение пользователя.

## 6. Модель состояния и интеграционный контракт

Главный модуль раздела владеет единым snapshot состояния и передает дочерним зонам только необходимые значения и действия.

| Состояние | Владелец | Получатели | Обязательный видимый результат |
|---|---|---|---|
| Выбранный пакет | Workspace | Панель пакетов, контекст, таблица | Путь и документы относятся к одному пакету. |
| Раскрытые пакеты и поиск | Панель пакетов | Дерево пакетов | Фильтрация не меняет выбранный пакет без явного выбора. |
| `Включая вложенные` | Workspace | Правило выборки, счетчик, таблица | Набор и счетчик пересчитываются вместе. |
| Фильтр, сортировка, колонки | Workspace | Toolbar и таблица | Header и строки используют одну конфигурацию колонок. |
| Текущая страница и размер | Workspace | Таблица и Pagination | После изменения фильтра или пакета страница нормализуется к доступному диапазону. |
| Выбранные документы | Workspace | Чекбоксы и массовая панель | Счетчик равен фактически выбранным строкам. |
| Открытый документ | Workspace | Таблица и drawer | Активная строка и содержимое drawer относятся к одному документу. |
| Выбранная версия | Drawer | Атрибуты и файлы | Обе панели показывают одну версию документа. |
| Открытые menu/popover | Владелец соответствующей зоны | Только одна связанная зона | Закрытие меню не сбрасывает пакет, таблицу или drawer. |
| Уведомление | Workspace через общий Toast | Вся рабочая область | Видно одно актуальное подтверждение mock-действия. |

Сквозной контракт первой миграции:

```text
выбор пакета
→ выборка документов
→ фильтр, сортировка и страница
→ строка таблицы
→ открытый документ и версия
→ атрибуты и файлы в drawer
```

## 7. Рабочие пакеты миграции

### WP-00. Фиксация контракта

**Ответственный:** главный агент; субагент допускается только для независимого аудита.

**Работы:**

- зафиксировать ревизию `434701870192275456`;
- получить read-only source snapshot точной ревизии в отдельную staging-папку и не использовать рабочую директорию MagicPath-редактирования как экспорт;
- сохранить визуальный baseline при `1600 × 960`, тему, активное состояние и перечень намеренных различий;
- сопоставить видимые состояния MagicPath с `01/02/03`;
- составить перечень UI-компонентов реестра;
- принять обратно совместимые решения для немодального Drawer и динамической Pagination;
- провести `magicpath-design` review зафиксированного состояния либо записать причину, по которой baseline принимается без нового изменения холста;
- отметить mock-действия и будущие функции;
- определить минимальный viewport приемки `1600 × 960` и дополнительные контрольные ширины.

**Результат:** утвержденная граница первой миграции без неявных будущих функций.

### WP-01. Данные и чистые правила

**Зависимость:** WP-00.

**Работы:**

- вынести дерево пакетов, документы, атрибуты и файлы из TSX в data-слой;
- перенести фильтрацию дерева, получение пути и поиск узла в domain-слой;
- перенести выборку вложенных документов, сортировку, фильтр и пагинацию;
- обеспечить стабильные идентификаторы и детерминированные mock-результаты.

**Приемка:** функции проверяются без DOM; UI не придумывает документы или атрибуты. Если WP-00 требует расширения общей компонентной базы, оно реализовано и проверено до начала UI-пакетов.

### WP-02. Панель пакетов

**Зависимость:** WP-01.

**Работы:**

- реализовать закрепленный поиск, прокручиваемое дерево и закрепленный footer;
- реализовать уровни вложенности, раскрытие, выбор и текущие действия пакета;
- реализовать truncation и подсказку только для фактически обрезанного текста;
- реализовать resize, синюю индикацию и возврат к `320 px` двойным кликом;
- передавать выбранный `packageId` главному модулю.

**Приемка:** изменение панели не прокручивает и не деформирует правую область; выбор пакета однозначен.

### WP-03. Контекст, toolbar и таблица документов

**Зависимости:** WP-01, контракт выбранного пакета из WP-02.

**Работы:**

- реализовать путь пакета, счетчик и toolbar;
- реализовать включение вложенных пакетов, сортировку, фильтр типа и колонки;
- реализовать таблицу, выбор строк и меню строки;
- подключить общий Checkbox и общие кнопки;
- реализовать empty state без фиктивных документов.

**Приемка:** набор строк, счетчик, заголовки и выбранные строки согласованы после каждого изменения.

### WP-04. Пагинация и массовые действия

**Зависимость:** WP-03.

**Работы:**

- подключить `pattern.pagination` из реестра;
- использовать принятое в WP-00 решение для обновления общего количества страниц без локальной копии Pagination;
- показывать пагинацию только при количестве документов больше размера страницы;
- реализовать размеры страницы `25`, `50`, `100`;
- реализовать выбор всех видимых строк текущей страницы;

## 8. Организация работы с субагентами

Субагент получает один рабочий пакет или одну независимую проверку. Главный агент сохраняет владение архитектурой, общим состоянием, интеграционными файлами и приемкой.

### 8.1. Правила делегирования

1. Перед задачей передавать субагенту этот план, точный комплект компонента и только необходимые файлы кода.
2. Указывать точные разрешенные файлы изменения и запрет на новые зависимости, React и изменение основного `src/features`.
3. Не запускать параллельно задачи, которые редактируют `sections/documents/index.js`, общий state-контракт или один CSS-файл.
4. Data/domain, визуальный компонент и независимый аудит могут выполняться параллельно только при заранее утвержденных интерфейсах модулей.
5. Субагент не обновляет базовую ревизию MagicPath и не расширяет scope самостоятельно.
6. Если задача требует skill, в поручении указывается его точное имя, причина применения и ожидаемый quality-gate артефакт.
7. Skill не дает субагенту разрешения исправлять соседние компоненты или менять продуктовый контракт.
8. Каждый результат должен содержать измененные файлы, выполненные проверки, skill-verdict и нерешенные вопросы.
9. Главный агент проверяет diff, сборку, видимое состояние и соответствие документации до начала зависимого пакета.

### 8.2. Рекомендуемое распределение

| Задача субагента | Разрешенная область | Запрещенная область | Проверка главным агентом |
|---|---|---|---|
| Data/domain | `src/data`, `src/domain` стенда | DOM, CSS, основной runtime | Детерминированность и отсутствие UI-логики. |
| Панель пакетов | `package-sidebar.js`, локальный CSS-блок | Таблица, drawer, модель документов | Пространственный контракт и событие выбора. |
| Список документов | `documents-list.js`, локальный CSS-блок | Drawer и данные пакетов | Согласованность toolbar, таблицы и Pagination. |
| Drawer | `document-detail-drawer.js`, локальный CSS-блок | Общая выборка таблицы и будущие слои | Геометрия, focus, переключение документа. |
| Независимый QA | Только чтение кода, браузер и отчет | Исправление без новой задачи | Воспроизводимость найденных отклонений. |

Интеграционный `index.js` и окончательное объединение CSS остаются за главным агентом, чтобы исключить расхождение контрактов.

## 9. Матрица проверки локального стенда

| Область | Проверка | Ожидаемый результат |
|---|---|---|
| Запуск | `documents/open.cmd` при остановленном сервере | Vite запускается, `/documents/` открывается. |
| Повторный запуск | `documents/open.cmd` при работающем сервере | Используется текущий сервер, второй экземпляр не требуется. |
| Панель пакетов | Поиск длинного вложенного пакета | Совпадения видны вместе с путем раскрытия; длинное имя имеет tooltip. |
| Resize | Drag, hover и двойной клик по границе | Ширина ограничена диапазоном, линия синяя, двойной клик возвращает `320 px`. |
| Выбор пакета | Выбрать несколько пакетов последовательно | Путь, счетчик и таблица относятся к последнему выбранному пакету. |
| Вложенные документы | Переключить `Включая вложенные` | Счетчик, страницы и строки пересчитаны согласованно. |
| Таблица | Изменить сортировку, тип и колонки | Строки и header соответствуют выбранной конфигурации. |
| Пагинация | Набор больше `25`, смена страницы и размера | Диапазон, активная страница и количество строк корректны. |
| Выбор строк | Одна строка и все строки страницы | Чекбоксы и счетчик массовой панели совпадают. |
| Drawer | Открыть документ и выбрать другой | Drawer остается открыт, содержимое и активная строка заменены. |
| Геометрия drawer | Viewport `1600 × 960` | Drawer `1060 px`, файлы `350 px`, gap `12 px`, видима левая часть наименований. |
| Меню | Открыть `Действия`, выбрать пункт, нажать `Escape` | Группы корректны; меню закрыто; drawer и документ сохранены. |
| Фокус | Открыть и закрыть drawer с клавиатуры | Таблица не прокручивается к правой границе; фокус возвращается к источнику. |
| Типографика | Проверить длинные названия пакета, документа, атрибута и файла при `100%` и `200%` zoom | Иерархия различима, текст не перекрывает действия, tooltip доступен для обрезанных значений. |
| Контраст | Проверить основной, вторичный, selected, focus и destructive-текст | Значимые элементы проходят WCAG AA или зафиксировано подтвержденное исключение визуального источника. |
| Motion | Открыть drawer, menu, toast и включить `prefers-reduced-motion` | Переходы не блокируют действие; reduced motion устраняет необязательное перемещение. |
| Visual diff | Сравнить MagicPath и локальный стенд при одинаковых данных и `1600 × 960` | Отличия ограничены заранее утвержденным списком; первый расходящийся ancestor диагностирован до локальных CSS-компенсаций. |
| Empty state | Пакет без документов или фильтр без результатов | Видна одна корректная заглушка, фиктивных строк нет. |
| Регрессия | Открыть `/tasks/` и `/document-templates/` | Существующий интерфейс задач и заглушка шаблонов не изменены. |
| Сборка | `npm.cmd run build` | Vite завершается без ошибок. |

## 10. Контроль UI-консистентности

- Сначала используется реальный общий компонент, затем добавляется только продуктовая компоновка вокруг него.
- Размеры `320`, `272–560`, `1060`, `350` и `12 px` считаются продуктовым контрактом первой миграции.
- Тексты, количество пунктов меню и порядок групп сверяются со спецификацией, а не восстанавливаются по памяти.
- Иконки имеют одинаковый визуальный размер внутри одной группы действий; новая библиотека иконок не добавляется.
- Стандартные hover, focus, disabled и selected-состояния общих компонентов не дублируются локальными альтернативами.
- Визуальное сравнение выполняется минимум для базового списка, раскрытого дерева, открытого drawer и раскрытого меню действий.
- Любое осознанное отличие от MagicPath сначала фиксируется как изменение спецификации, затем реализуется.
- `magicpath-design`, `typeset` и `polish` не применяются как генераторы нового визуального направления во время миграции; они проверяют качество в пределах зафиксированного контракта.
- Финальная polish-проверка выполняется после функциональной приемки, а не вместо нее.

## 12. Риски и способы ограничения

| Риск | Ограничение |
|---|---|
| Механический перенос TSX создает React-остров | Реализация начинается с data/domain-контрактов и нативных UI-компонентов. |
| Разные субагенты создают разные контролы | Реестр проверяется до реализации; общие файлы интегрирует главный агент. |
| Mock-логика воспринимается как готовая функция | Mock-действия перечислены в scope; будущие слои вынесены в отдельные инкременты. |
| Drawer делает таблицу недоступной | Геометрия и переключение строк входят в обязательную браузерную приемку. |
| Стили ломают другие страницы стенда | Общий scope, проверки `/tasks/` и `/document-templates/`. |
| MagicPath меняется во время переноса | Ревизия закреплена; новые изменения оформляются отдельным diff-инкрементом. |
| После переноса остаются две активные копии | До миграции в основной S-Tracker локальный стенд является единственной нативной копией; после основной миграции применяется правило шлюза из `migration/README.md`. |

## 13. Definition of Done первой миграции

- `/documents/` больше не показывает заглушку.
- Все пункты раздела 3.1 реализованы в нативном runtime.
- Ни один пункт раздела 3.2 не выдается за готовую функцию.
- В runtime нет React, TSX, `lucide-react` и новых зависимостей.
- Общие UI-компоненты используются через `@s-tracker/ui`.
- Data, domain и UI разделены согласно разделу 4.
- Состояние пакета, таблицы и drawer связано единым контрактом.
- Матрица раздела 9 пройдена без блокирующих отклонений.
- `npm.cmd run build` проходит.
- `01/02/03` соответствуют фактическому стенду.
- Сохранены нативные визуальные эталоны ключевых состояний.
- Проведен frontend code audit, блокирующие замечания устранены.
- Пройден screenshot-first UX/UI-аудит; findings устранены или имеют зафиксированное продуктовое решение.
- Для примененных skills сохранены quality-gate отчеты; рекомендации вне baseline не внедрены без согласования.

## 15. Шлюз миграции в основной S-Tracker

Переход к основному прототипу разрешен, когда:

- первая миграция и необходимые последующие инкременты завершены;
- документы компонентов описывают фактический стенд;
- определены целевые файлы в основном `src/data`, `src/domain`, `src/features`, `src/ui` и `src/styles`;
- проверено отсутствие конфликта с вкладкой `Поиск`;
- подготовлены регрессионные проверки задач, доменов, фильтров, колонок, массовых действий и пагинации;
- перенос выполняется одним завершенным блоком без второй активной runtime-копии.

До прохождения шлюза основной S-Tracker не импортирует файлы из `local-stands`.
