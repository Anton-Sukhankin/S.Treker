# Lego-форма документа: данные, состояния и правила

## 1. Термины

| Термин | Определение |
|---|---|
| Черновые значения | Текущие значения полей, включая изменения после последнего сохранения или подтверждения. |
| Сохранённые значения | Нормализованные значения после сохранения черновика или успешного подтверждения этапа. |
| Подтверждённый этап | Этап, который прошёл валидацию в последовательной цепочке от `Потребность`. |
| Первый незавершённый этап | Этап сразу после непрерывной последовательности подтверждённых этапов; он доступен для выбора. |
| Сводка | Самостоятельный финальный экран с текстовыми парами `label/value` по всем этапам. |

## 2. Состояния процесса

| Состояние | Условие | Видимый результат |
|---|---|---|
| Базовая форма | Новое открытие Lego-варианта | Активна `Потребность`; будущие этапы заблокированы; показаны начальные значения и placeholders. |
| Черновик изменён | Значения отличаются от сохранённых | Новые значения видны; подтверждённость изменённого и последующих этапов снята. |
| Ошибка этапа | Подтверждение выполнено при пустом обязательном значении | Форма остаётся на этапе; конкретные поля показывают сообщения. |
| Этап подтверждён | Валидация этапа успешна | Карточка показывает `Этап подтверждён`; следующий этап доступен и активен. |
| Сводка | Подтверждён валидный пятый этап в самостоятельном режиме | Карточки этапов, форма и footer скрыты; видны header и две области сводки. |
| Задача завершена | Подтверждён валидный пятый этап во встроенном режиме | Все карточки подтверждены; сводка отсутствует; карточка задачи показывает уведомление. |

## 3. Правила обязательности

| Этап | Обязательные значения | Условное правило |
|---|---|---|
| `Потребность` | `Предмет договора`, `Объект строительства` | `Вид потребности` имеет начальное значение `Услуга`. |
| `Контрагент` | `Тип договора`; `Контрагент`, если `Контрагент уже определён` включён | При выключенном переключателе справочник контрагента не участвует в проверке. |
| `Стоимость и бюджет` | `Сумма`, `Валюта`, `ЦФО`, `Статья оборотов`, `Бюджетная единица` | `Ставка НДС` обязательна только при включённом `Сумма включает НДС`. |
| `Условия оплаты` | `Схема оплаты`, `Основание платежа` | `Размер аванса` обязателен для схем `Предоплата` и `Аванс и окончательный расчёт`. |
| `Сроки и формат` | `Периодичность`, `Плановая дата завершения`, `Формат результата` | `Периодичность` имеет начальное значение `Разовая услуга`; плановая дата завершения в текущем прототипе заполнена значением `30.09.2026`. |

## 4. Правила значений

| Тип значения | Пустое состояние | Активное состояние | Видимый результат |
|---|---|---|---|
| Select без начального значения | Серый placeholder `Выберите…`; пустой пункт доступен и после выбора | Выбранный пункт справочника | Текст выбранного пункта имеет основной цвет; повторный выбор пустого пункта возвращает placeholder. |
| Необязательное текстовое поле | Пустая строка | Введённый текст | В сводке пустое значение показано знаком `—`. |
| Переключатель | `Нет` | `Да` | В сводке показано `Нет` или `Да`; строка переключателя не получает карточную подложку. |
| Сумма | Пустая строка | Числовое значение | В сводке число форматируется вместе с обозначением выбранной валюты. |
| Дата | Пустая строка | Выбранная дата | В сводке дата показана в локальном формате. |
| Файл | Имя отсутствует | Пользователь выбрал файл | В форме и сводке показано имя файла; байты файла локальный прототип не сохраняет. |

В самостоятельном режиме `Особые условия` хранится как необязательное текстовое значение этапа `Условия оплаты` и выводится отдельной ячейкой сводки. Во встроенном режиме карточки задачи это поле не показано.

## 5. Последовательность и сохранение

- Завершённость всегда образует непрерывную последовательность от этапа `Потребность`.
- Изменение значения этапа удаляет подтверждённость этого этапа и всех следующих этапов.
- Сохранение черновика обновляет сохранённые значения, но не подтверждает активный этап.
- Успешное подтверждение нормализует строковые значения, сохраняет их и очищает ошибки активного этапа.
- Возврат из сводки открывает `Сроки и формат` и не очищает значения пяти этапов.
- Новое открытие самостоятельного Lego-варианта после закрытия создаёт независимый базовый черновик.
- История, комментарии, сворачивание аккордеона и изменение ширины карточки задачи не меняют состояние формы.

## 6. Контракты взаимодействия

| Связанный компонент | Роль связанного компонента | Условие | Результат в Lego-форме | Результат в связанном компоненте |
|---|---|---|---|---|
| `new-document-type-picker` | Источник самостоятельного режима | Пользователь выбирает опубликованный Lego-вариант | Создан новый базовый черновик; открыт этап `Потребность`. | Каталог и его header скрыты; drawer остаётся открытым. |
| `documents-workspace` | Владелец drawer и получатель документа | Пользователь сохраняет сводку | Форма передаёт значения пяти этапов и имя выбранного варианта. | Drawer закрыт; текущий пакет показывает новую локальную строку и увеличенный счётчик. |
| `task-card-drawer` | Родитель встроенного режима | Значение или активный этап изменены | Snapshot содержит активный этап, валидность, подтверждённые этапы и признак несохранённых изменений. | Footer получает актуальное название и доступность primary-действия. |
| `task-card-drawer` | Получатель завершения | Подтверждён пятый этап встроенного режима | Признак завершения задачи получает значение `Да`; сводка не открывается. | Drawer показывает toast завершения. |

## 7. Ограничения ответственности

| Область | Правило |
|---|---|
| Backend | Форма не выполняет серверное сохранение, генерацию файла или реальную верификацию. |
| ECM | Форма не меняет поля и поведение стандартной ECM-формы. |
| Карточка задачи | Форма не владеет header, footer, историей, комментариями и закрытием карточки. |
| Каталог шаблонов | Форма принимает выбранный вариант, но не меняет публикацию и версию шаблона. |
| Печатная ветка | Статус, верификация и скачивание на сводке являются локальными демонстрационными состояниями. |
