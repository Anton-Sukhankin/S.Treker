# Карточка задачи в drawer: данные, состояния и правила

## 1. Данные задачи

| Зона | Данные |
|---|---|
| Header | `id`, `title` |
| `О задаче` | `assignee`, `status`, `dueDate`, `description` |
| История | `id`, `date`, `time`, `text`; пять mock-позиций |
| Комментарии | `id`, `initials`, `name`, `role`, `date`, `time`, `text`; четырнадцать mock-позиций |
| Форма | Заголовок, пять этапов, значения полей, справочники, зависимые переключатели и подтверждённость |

UI не добавляет атрибуты из визуально похожих референсов. Например, поля шаблона `Приказ` не становятся полями этапа `Потребность`.

## 2. Состояния

| Состояние | Видимый результат |
|---|---|
| Закрыт | Видна точка входа, drawer и overlay скрыты |
| Основной режим | Видны header, footer и два аккордеона |
| История | Контентная высота занята только историей |
| Комментарии | Контентная высота занята только комментариями |
| Несохранённые изменения | Закрытие требует подтверждения |
| Этап невалиден | Primary-кнопка footer disabled, tooltip сообщает условие |
| Этап валиден | Primary-кнопка доступна |
| Задача завершена | Все этапы подтверждены, показано уведомление |

## 3. Контракт с `lego-document-form`

Форма передаёт drawer snapshot: активный этап, валидность активного этапа, подтверждённые этапы, признак несохранённых изменений и завершение задачи. Drawer не вычисляет значения и обязательность полей. Footer сохраняет черновик или запрашивает подтверждение активного этапа, после чего получает новый snapshot.

Редактирование ранее подтверждённого этапа снимает завершённость этого и последующих этапов. Сохранение черновика не подтверждает этап. Возврат из истории или комментариев не пересоздаёт состояние формы.

## 4. Доступность

- Drawer имеет роль dialog и модальность.
- Все icon-only кнопки имеют `aria-label` и title.
- Resizer имеет роль separator, orientation и числовые `aria-value*`.
- Аккордеоны связывают toggle и content через `aria-controls`.
- Активная карточка этапа имеет `aria-current="step"`; недоступные карточки disabled.
- Toast объявляется через live region общей компонентной базы.
