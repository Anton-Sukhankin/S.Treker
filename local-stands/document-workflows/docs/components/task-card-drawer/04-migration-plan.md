# Карточка задачи: план миграции в основной S-Tracker

> Статус: выполнено 03.08.2026. Источник визуального и интерактивного поведения — текущая реализация локального стенда и комплект `01-structure.md`, `02-behavior.md`, `03-data-states-rules.md` этого компонента и дочерней `lego-document-form`.

Все семь этапов выполнены. Основная реализация прошла сборку, сценарную проверку и визуальное сравнение с локальным эталоном в одинаковом состоянии первого этапа. Итог проверки зафиксирован в корневом `design-qa.md` основного прототипа.

## 1. Цель и критерий паритета

Перенести drawer карточки задачи из локального стенда в основной vanilla/Vite-прототип S-Tracker без изменения его UI, UX, состава данных, механик формы и режимов истории и комментариев.

Миграция завершена, когда:

- наименование каждой задачи открывает drawer в карточном и табличном режимах независимо от очереди, бизнес-домена, группировки, фильтров и страницы;
- открывается выбранная задача, а не фиксированная демонстрационная позиция;
- чекбокс выбора задачи, копирование email, фильтры, колонки, пагинация и переключение вида продолжают работать отдельно от открытия drawer;
- структура, размеры, отступы, типографика, цвета, границы, отсутствие теней и состояния локального drawer визуально совпадают с основным прототипом при одинаковом viewport и одинаковых данных;
- сохранены закрытие, возврат фокуса, resize, аккордеоны, история, комментарии, черновик, подтверждение этапов, Select, toast и защита от выхода с несохранёнными изменениями;
- основная сборка проходит без новых зависимостей, React, Tend UI или изменений в `dist` вручную.

| `src/domain/lego-document-state.js` и адаптер `src/domain/task-card-state.js` | Черновик, валидация, последовательность этапов и завершение задачи без сводки | `src/domain/task-card-state.js` |

## 3. Последовательность выполнения

### Этап 1. Аудит источника и точки интеграции

1. Зафиксировать функции, состояния и CSS-правила локальной карточки.
2. Проверить рендер карточного и табличного списка в основном `tasks-view`.
3. Проверить текущие обработчики массового выбора, email, пагинации и повторного рендера.
4. Подключить независимых субагентов только для read-only аудитов локального паритета и основной интеграции; итоговые решения и правки остаются за главным агентом.

### Этап 2. Данные и состояние

1. Добавить подтверждённую конфигурацию карточки и Lego-формы в `src/data`.
2. Добавить domain-селектор деталей карточки по `taskId`; UI не создаёт значения самостоятельно.
3. Для текущего прототипного набора формировать деталь из данных выбранной задачи: `id`, `title`, статус, исполнитель и срок берутся из основной модели; история, комментарии, описание и процесс берутся из зарегистрированной detail-конфигурации.
4. Создавать отдельное состояние формы для каждого открываемого `taskId`, чтобы повторное открытие одной задачи сохраняло её черновик в текущей сессии и не переносило значения в другую задачу.

### Этап 3. Компонент drawer

1. Перенести карточку в отдельный feature-модуль.
2. Переиспользовать зарегистрированные `Button`, `Input`, `Select`, `Drawer`, `Modal` и `Toast`.
3. Создать один контроллер drawer на приложение; при открытии менять выбранную задачу и её state, не регистрируя повторные document-level обработчики.
4. Сохранить возврат фокуса к наименованию задачи, вызвавшему открытие.

### Этап 4. Универсальная точка входа

1. Сделать наименование задачи нативной кнопкой внутри карточки и колонки `Наименование` таблицы.
2. Передавать в кнопку `taskId`; видимый текст и существующая метафора задачи сохраняются.
3. Один делегированный обработчик в области задач открывает drawer после любого повторного рендера списка.
4. Клик по наименованию не меняет выбранность строки; клик по чекбоксу не открывает drawer.

### Этап 5. Стили

1. Перенести только селекторы drawer и Lego-формы в отдельный feature-файл.
2. Сохранить базовую ширину `740 px`, диапазон `520–1100 px`, фиксированные header/footer и текущие responsive-правила.
3. Не дублировать стили общих компонентов и не сбрасывать штатный индикатор `Select`.
4. Проверить слои overlay и drawer рядом с фильтрами и настройками колонок.

### Этап 6. Документация основного проекта

1. Создать `docs/components/task-card-drawer/01–03` и дочерний комплект `lego-document-form/01–03` на основе актуальных локальных спецификаций.
2. Обновить `docs/components/tasks/01–03`: точка входа находится в наименовании обеих компоновок.
3. Создать сквозной flow открытия, работы и закрытия карточки.
4. Обновить `docs/component-code-map.md` и `docs/project-structure.md`.
5. Этот файл плана остаётся только в локальном стенде и не дублируется в основном `docs/`.

### Этап 7. Проверка

1. Выполнить сборку основного проекта.
2. Проверить карточный и табличный режимы, очереди, домены, фильтры, поиск, группировки, пагинацию и повторное открытие.
3. Проверить клавиатуру, focus return, `Escape`, overlay, resize и dirty-close.
4. Проверить все пять этапов, валидацию, черновик, Select, историю и четырнадцать комментариев.
5. Снять одинаковое состояние локального и основного drawer при одинаковом viewport, объединить изображения в одно сравнение и исправить все P0/P1/P2 расхождения.
6. Сохранить итоговый `design-qa.md` в корне основного проекта с `final result: passed`.

## 4. Матрица обязательной регрессии

| Сценарий | Ожидаемый результат |
|---|---|
| Наименование в карточном виде | Открыта карточка выбранного `taskId`; набор выбранных задач не меняется |
| Наименование в таблице | Открыта та же структура drawer; горизонтальный скролл и закреплённые колонки не меняются |
| Чекбокс карточки или строки | Меняется только массовый выбор; drawer не открывается |
| Переключение очереди, домена, вида или страницы | Новые наименования остаются рабочими без повторной ручной подписки |
| Закрытие без изменений | Drawer закрыт; фокус возвращён к исходному наименованию |
| Закрытие с несохранённым draft | Показано подтверждение; выбор пользователя соблюдён |
| Resize | Ширина меняется мышью и клавиатурой в допустимом диапазоне |
| Аккордеоны | `О задаче` и форма сворачиваются независимо, стрелки отражают состояние |
| История и комментарии | Основная область заменена соответствующим списком; возврат восстанавливает карточку |
| Подтверждение этапов | Следующий этап доступен только после действительного подтверждения текущего |
| Повторное открытие разных задач | Значения формы не переносятся между задачами |
| Фильтры, колонки, пагинация, поиск документов | Существующие сценарии основного S-Tracker не нарушены |

## 5. Условия остановки

Миграция не признаётся завершённой, если основной drawer нельзя сравнить с локальным в одинаковом состоянии, сборка не проходит, остаются P0/P1/P2 различия, наименование не работает хотя бы в одном режиме списка или открытие карточки меняет массовый выбор.
