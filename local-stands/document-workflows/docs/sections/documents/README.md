# Паспорт раздела «Документы»

> Статус: миграция в локальный стенд завершена для пакетов, списка, пагинации, массового выбора, карточки документа, меню действий и локального создания документа; просмотр файла и редактирование атрибутов остаются следующими инкрементами.

## 1. Граница раздела

Раздел охватывает дерево пакетов, список документов, детальную карточку, файлы, просмотр печатной формы, редактирование атрибутов и выбор способа создания документа. Действующая вкладка `Поиск` основного S-Tracker не входит в этот блок.

## 2. Карта реализации

| Блок | Компонент или документ | Статус перед кодом |
|---|---|---|
| Пакеты, таблица и детальная карточка | `docs/components/documents-workspace/` | Реализованы в `/documents/` и проверены в браузере. |
| Редактирование атрибутов и просмотр файлов | `docs/components/documents-workspace/` | Состав и основные состояния подготовлены. |
| Выбор варианта создания | `docs/components/new-document-type-picker/` | Реализован как нижний drawer без боковой категорийной панели. |
| Самостоятельная Lego-форма и сводка | `docs/components/lego-document-form/` | Пять этапов и сводка занимают тот же drawer после выбора Lego-варианта; общий блок повторно используется в карточке задачи. |
| Создание документа | `docs/user-flows/create-document-from-documents-workspace.md` | Локальный путь до новой строки реализован; backend не подключен. |

## 4. Задачи без излишней декомпозиции

Таблица и карточка документа остаются зонами одного `documents-workspace`. Picker создания выделен в дочерний компонент из-за собственного поиска, пустого результата и пространственного контракта. Lego-форма остается общим компонентом, потому что используется также в карточке задачи.

## 5. Текущие ограничения

- Верификация и скачивание на сводке показывают локальную обратную связь без генерации файла и серверного процесса.
- Возможность ручной правки подстановок на верификации отсутствует.
- Ветка печати для типов документа без печатной формы требует отдельного продуктового контракта.

## 6. Готовность

Документационный контур picker, пять Lego-этапов, сводка и клиентский результат создания готовы. Для миграции в основной runtime остаются backend-контракт, реальная генерация документа и интеграционные правила данных.
