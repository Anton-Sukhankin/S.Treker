# Документация локального стенда

Эта папка является единственным продуктовым документационным контуром локального стенда документных сценариев.

## Структура

| Папка | Роль | Экспортируется для реализации компонента |
|---|---|---|
| `sections/` | Паспорта разделов: границы, состав задач, маршруты к спецификациям и идентификаторы источников. | Нет. |
| `components/` | Комплекты структуры, поведения, данных и состояний компонентов. | Да, только папка целевого компонента. |
| `user-flows/` | Сквозные сценарии между двумя или несколькими компонентами. | Только вместе с комплектами участвующих компонентов. |
| `research/` | Источники, замечания, гипотезы и открытые вопросы. | Нет. |
| `component-code-map.md` | Карта связи спецификаций с фактическими владельцами runtime локального стенда. | Нет. |

Обязательный стандарт документации находится только в корневом `docs/documentation-standards.md`. Конкретный результат аудита фиксируется в итогах соответствующей задачи; постоянная локальная копия стандарта или журнала аудита не ведется.

## Маршрут контекста

1. `references/context-register.md` присваивает каждому исходному материалу стабильный идентификатор.
2. `references/evidence/<section>/README.md` выделяет относящиеся к разделу факты, замечания и гипотезы.
3. `sections/<section>/README.md` связывает задачи раздела с доказательствами, компонентами и flow.
4. Подтвержденное правило переносится в `components/<component>/01/02/03` до начала реализации.

## Правило статуса

До появления runtime каждый комплект сохраняет пометку `целевая спецификация локального стенда`. После реализации и проверки стенда статус обновляется локально. Документ не становится спецификацией основного S-Tracker до выполнения миграционного шлюза.

## Визуальные эталоны

Готовый эталон хранится в `components/<component>/assets/` и показывает один компонент или одно его состояние с минимальным соседним контекстом. Исходный полноэкранный снимок хранится только как сырой материал в `references/` и не объявляется эталоном.
